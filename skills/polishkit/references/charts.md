# Charts (数据可视化)

Scope: charts inside product UI — dashboards, analytics, monitoring, finance — not scientific plotting packages. Sources: d3js.org (`/what-is-d3`; d3js.org itself is silent on data-ink and chartjunk, so the Tufte rules below are grounded in Tufte's *The Visual Display of Quantitative Information* (1983) via J. P. Boyd's "The Gospel According to Tufte", a University of Michigan course chapter that quotes the book directly, https://websites.umich.edu/~jpboyd/eng403_chap2_tuftegospel.pdf, ch. 2 pp. 27–40); the Okabe-Ito palette origin page (https://jfly.uni-koeln.de/color/); Penn State GEOG 486 "Types of Color Schemes" for the diverging-scheme rule (https://courses.ems.psu.edu/geog486/node/878); and the vendored `data/charts.csv` (25 data-type scenarios), cited by column. Extends `color-and-type.md` § Data colors — the OKLCH role system and contrast floors there are unchanged and win every conflict (see 张力裁定).

## 选型优先 (question first)

- Start from the question the user must answer, then the data shape, then the chart. `charts.csv`'s Data Type column is the checklist of 25 questions (trend over time, compare categories, part-to-whole, correlation, heatmap, funnel, forecast, anomaly, …). Name the question, find the row, take its Best Chart Type. Cite the CSV, not a chart gallery.
- Read When NOT to Use before committing. The rows encode failure boundaries: fewer than 4 points is a stat card, not a line chart; more than 6 series on one line chart is noise; more than 15 categories is a table or search; pie beyond 5 categories or with slice differences under 5% is out; radar beyond 8 axes is unreadable.
- Respect the Data Volume Threshold column as precedent: under ~1000 points SVG is fine, from 1000 Canvas plus downsampling, past 10000 aggregate to intervals; beyond ~50 categories a paginated table beats a chart.
- D3's documentation is the paradigm anchor, not a recipe source: "D3 is not a charting library in the traditional sense. It has no concept of 'charts'" and "D3 has no default presentation of your data — there's just the code you write yourself" (https://d3js.org/what-is-d3). A chart is composed from primitives — scales encode "abstract data into visual values such as position, size, and color", axes "explain position encodings" — so choose the encoding on purpose, the way `directions.md` asks you to choose a direction on purpose.
- For product UI, high-level chart libraries are legitimate; the D3 docs themselves call D3 "overkill for throwing together a private dashboard" and point to Observable Plot for that. The rules in this file apply to whatever library renders the marks. The CSV's Library Recommendation column stays precedent-only (see 刻意不采用).

## Data-ink (数据墨水)

- Tufte 1983, quoted via Boyd: data-ink is "the non-erasable core of a graphic"; the data-ink ratio is "data-ink / total ink used to print the graphic"; the maxims: "Above all else show the data", "Maximize the data-ink ratio", "Erase non-data-ink", "Erase redundant data-ink", "Revise and edit". d3js.org never mentions Tufte; the idea belongs to the book, not the library.
- Gridlines lighter than data, always: "Don't use a grid unless you really have to" and "Make the grid lines faint compared to the data-curves" — thin or dotted grid, thick data curve (Boyd, ch. 2.1.3). In UI terms: horizontal gridlines only, 1px hairline or dotted, muted against the canvas; the marks carry the weight.
- No 3D for business charts. Wikipedia's chartjunk article (the term is Tufte's 1983 coinage) lists "3-D simulations in line and bar charts" as chartjunk, and perspective distorts the position encoding the whole chart rests on. `charts.csv` row 22 keeps 3D only where the Z axis is essential, and its own fallback is a mandatory 2D projection plus a data table — the same ruling.
- Direct labels over legends where possible. Three sources converge: Tufte's bar-chart redesign ("one should eliminate the legend, and directly label each bar. (This is sound general practice.)", Boyd ch. 2.1.5), the Okabe-Ito page ("Separate keys are avoided. Labels are shown directly within the drawings"), and `color-and-type.md` ("Legends make the eye travel").
- Erase redundant ink: no double frames (half-framing is the direction, not a hard format), no drop shadows on bars, no decorative gradient fills behind lines, no background fill at full opacity under a 20%-opacity series. Boyd's caveat stands: "The only disadvantage of Tufte's format is unfamiliarity" — so erase toward clarity, not toward a style.
- The escape hatch: "Sometimes the best way to cope with a flawed graph is to eliminate the illustration entirely, and use a table instead" (Boyd ch. 2.1.7). This is the same mechanism as the accessibility fallback below — one decision, two justifications.
- Redundant coding is not chartjunk. Hatching, markers and line styles that re-encode a series are accessibility ink (Okabe-Ito's own figures rely on them); what Boyd flags is "shimmering Moiré patterns" — dense fill patterns that vibrate. Patterns yes, moiré no.

## 颜色 (chart colors)

- Categorical: at most six or seven hues (the Okabe-Ito set in `color-and-type.md` § Data colors). The origin page's own figure (Fig. 16) prints the values; the plugin's seven hexes match it exactly (verified this batch; the eighth, black #000000, stays a text/canvas role, not a series hue). Combination rules from the same page: "Use 'warm' and 'cool' colors alternatively"; two warm or two cool colors need "distinct differences in brightness or saturation" — the set itself distinguishes sky blue from blue by brightness and saturation, so do not force the series to one lightness; avoid low-saturation or low-brightness combinations; for thin lines and small marks, darker blue and orange read better than sky blue and yellow.
- Sequential: one hue stepping lightness, matching PSU GEOG 486's rule that "the perceptual structure of the color scheme should match the perceptual structure of the data". Never a rainbow: hue has no order, and the origin page's CVD simulations show rainbow schemes collapsing to arbitrary pairings.
- Diverging: two hues joined at a neutral midpoint, used only when the data has a meaningful middle (zero, baseline, target). PSU GEOG 486: diverging schemes "visualize the distance of all values from a meaningful midpoint, usually an average or median using two contrasting color hues", with the middle in white or light grey, and limited to two hues — a third hue reads as categorical. Build it from two role hues plus the muted role as the midpoint; a numeric legend is mandatory (charts.csv row 5 says the same).
- The red/green trap is measurable, not a taste call: `charts.csv` row 13 (waterfall) ships increases as #4CAF50 and decreases as #F44336. Run the plugin's test: `python scripts/color_sim.py --check "#4CAF50" "#F44336"` reports 1.32:1 before simulation and 1.06:1 under deuteranopia — the pair collapses, the meaning depended on hue. Carry direction by position relative to zero, signed value labels and directional icons; color comes from the success/danger roles and the shipped pair must pass `color_sim.py --check`.
- Protanope specifics from the origin page: pure dark red reads almost black, black text and red text look the same, and red on green is unreadable. Vermilion (the palette's #D55E00) is the safe red side of a pair. Combined with `color-and-type.md`'s "Color is never the only signal": hue reinforces position, labels and pattern; it never replaces them.

## 无障碍 fallbacks

- The strongest pattern in the A11y Fallback column, present across all 25 rows: a visible data table plus a plain-language summary is the accessible primary view, and the chart is supplementary. For treemap, sunburst, word cloud, network and sentiment rows the table or tree is explicitly the source of truth. When a chart cannot be made readable, ship the table — data-ink's escape hatch and the fallback agree.
- The keyboard contract, by scenario: focus reveals the same values hover shows (every row); `+`/`−` buttons zoom with Reset restoring the full range (line, heatmap, forecast, OHLC); sortable table headers with Enter/Space and `aria-sort` (bar, OHLC); Pause/Resume on live streams (row 23) — which also serves WCAG 2.3.1 flashing; move buttons replacing drag (network, process map); Enter/Space drills in and Back returns (drill-down rows).
- Direct values where space allows: print values in heatmap cells, put signed values and directional icons on waterfall bars, expose OHLC as text. The CSV's Accessibility Notes column says "do not rely on color alone" in some form in all 25 rows; its Accessibility Risk self-grades (8 low, 11 conditional, 6 high) are vendor evidence to weigh, not a certification.
- Sonification is not in the CSV and is not asserted here.

## 与 vendored 数据的张力裁定

- The tension: `charts.csv`'s Color Guidance column ships 2014-era literal hexes — #0080FF as the primary series, the #4CAF50/#F44336 waterfall pair, blue→red heat gradients (rows 4, 5, 22), #00FF00 "current pulse" on dark — while `color-and-type.md` defines colors as OKLCH-built roles with checked contrast pairs.
- Ruling: the role system wins. Order of authority: (1) the WCAG floors and "color is never the only signal" from `color-and-type.md`; (2) the OKLCH role system — map each CSV literal to its role (#4CAF50→success, #F44336→danger, #0080FF→first data-series hue, blue→red→a diverging pair with a neutral midpoint) and re-derive the value in OKLCH for the theme; (3) the CSV literal, treated as precedent evidence of intent, never as a default value.
- What survives from the CSV as intent even where its hexes do not: the gradient direction and lightness banding ("each level 15–20% lighter"), the opacity bands (20% series fill, 0.4–0.6 flows), the requirement of a numeric color legend on every intensity scale, and the row-5 ruling that ±data needs a divergent scale. The measured failure of the waterfall pair above is the proof the hexes are residue and the discipline is the precedent.
- The rows are precedent evidence to weigh, not defaults: When NOT to Use, A11y Fallback, Data Volume Threshold and Accessibility Risk all carry over unchanged, because none of them depends on a color value.

## 与 --charts 的工作流关系

- SKILL.md step 3: "When the product displays data, also pass `--charts`." Run it for any dashboard, analytics, monitoring or finance brief — whenever a screen contains a chart.
- `design_lookup.py --charts` matches the query against the Data Type and Keywords columns and prints the top three rows as "Data Type: Best Chart Type" plus the A11y Fallback, trimmed. It gives you the row; this file gives the rules for rendering it: pick the row whose question matches (选型优先), then open that row in `data/charts.csv` for the untruncated fallback and thresholds.
- Exit path: chart choices land in the brief; verification runs the same loop as everything else — `wcag.py` on the final text and mark pairs, `color_sim.py --check` on adjacent series hues, and a captured render with worst-case data populated, not the empty state.

## 刻意不采用

- Per-library chart recipes (how to build X in Chart.js vs Recharts vs D3): libraries churn, the question→data→chart logic does not, and the skill stays library-agnostic. The CSV's Library Recommendation column stays precedent-only.
- Animated chart defaults (draw-on-load line sweeps, counting-up numbers): prescribed by no source here, and they collide with `layout-and-motion.md`'s motion frequency gate and reduced-motion floor. Charts move when the data changes, not for decoration.
- Sonification guidance: absent from `charts.csv` (checked: zero hits), so nothing is claimed; a future batch that adds it needs a source first.
- Tufte's minimalist bar chart and half-frame as mandatory formats: adopted as direction (erase redundancy), not as literal formats — unfamiliarity has a decoding cost, per Boyd's own caveat, and dense dashboards legitimately keep faint grids.
- D3 as the plugin's reference implementation: "D3 makes things possible, not necessarily easy" — its value here is the no-defaults stance, not its code.
