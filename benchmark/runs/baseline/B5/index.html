Six ideas, no plugin system.

Everything jfmt does fits on this page — deliberately.

Pipes in, pipes out
cat messy.json | jfmt writes clean JSON to stdout; jfmt -q stays silent and just sets the exit code, so it drops straight into CI.
In-place, with a net
jfmt -w src/config.json rewrites the file and leaves a .bak beside it. Silence the net with --backup=false once you trust it.
Diffs that mean something
jfmt --diff a.json b.json prints a JSON Patch of real value changes — reindented noise never shows up.
Watch while you work
jfmt --watch . re-formats on every save. At 3 ms per file, it finishes before your editor redraws.
Tolerant on the way in
Comments, trailing commas and unquoted keys are read without complaint. Output is always strict RFC 8259 JSON.
Config that fits in your head
Five keys, one file, no presets or shareable bundles. If a config needs documentation, it's too big.
.jfmtrcthe whole thing
{
  "indent": 2,
  "maxLine": 80,
  "sortKeys": false,
  "arrayTrailingComma": true,
  "color": "auto"
}

Found by walking up from the file — nearest wins, like .editorconfig.

plays well with jqdifferent jobs
$ curl -s https://api.github.com/repos/
    jfmt/jfmt/issues | jq '[.[] | {n, state}]' | jfmt

[
  { "n": 412, "state": "open" },
  { "n": 411, "state": "closed" }
]

jq queries it, jfmt makes it readable. Neither tries to do the other's job.
